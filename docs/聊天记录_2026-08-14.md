## 2. 修复：移动端导出战术板 HTML 无响应

### 问题

Android 端点击"导出战术板"没有任何反应。期望行为：调起系统文件管理器，由用户选择导出位置并成功保存。

### 原因

`src/platform/index.ts` 的 `downloadText` 使用浏览器下载方式（`Blob` + `<a download>` 模拟点击）。Android 的 Capacitor WebView 没有浏览器下载管理器，该点击被直接忽略。代码注释中本就预留了"Android 接入 Filesystem/Share 后替换本实现"的口子。

### 改动

- 新增依赖：`@capacitor/filesystem@8.1.2`、`@capacitor/share@8.0.1`（devDependencies）。
- `src/platform/index.ts`：Android 原生端改为
  1. 用 Filesystem 把 HTML 写入缓存目录 `exports/`（UTF-8）；
  2. 调起 Share 系统分享面板（标题"导出到"），用户可选择"文件"应用并自选保存位置；
  3. 用户取消分享不算错误，其他异常打印日志。
  Web / Electron 端逻辑不变。
- 该修复同时覆盖模式配置器的 JSON 导出（`ModeConfigWorkbench` 的 `onExport` / `onExportOfficial`，走同一个 `downloadText`）。

### 顺带修复：构建被阻塞的旧问题

- `vite.config.ts` 无条件引用入口 `demo/v0.0.1/app/cinematic-demo.html`，而 `demo/` 在 `.gitignore` 中、本地不存在，导致 `npm run build` 直接失败。
- 已改为该文件存在时才加入构建入口（`existsSync` 判断）。

### 验证

- `tsc && vite build` 通过。
- `npx cap sync android` 成功，两个插件已注册进 Android 工程。
- 真机行为未验证，需重新打包安装后测试。
