# 反思与思考链路：绘图组件锁定功能（2026-08-14）

记录本轮需求从理解到落地的完整推理过程与取舍，与更新日志（发生了什么）分开，侧重"为什么这么做"。

## 一、需求解读

用户原话拆解出 5 条硬要求 + 2 条隐含推论：

1. 绘制完成后，再次点击（选中）能出现锁定图标 → 锁定入口挂在选中态 UI 上。
2. 锁定后不可移动 → 拦截本体拖拽、手柄、捏合、套索连带移动。
3. 不可修改组件信息 → 属性面板、文字双击编辑要拦。
4. 不可擦除，且擦除时要提示"该图样已经锁定，请解锁后再删除" → 拦截只是前提，**提示才是用户可感知的核心**，漏掉提示等于功能没做。
5. 锁定后隐藏设置、只保留解锁图标 → 选中框按钮组要按锁定态整体换血，而不是简单禁用。
6. 隐含：锁定状态必须持久（重进不丢）、可撤销（锁错了能 Ctrl+Z）。
7. 隐含：箭头、防线这类多图层"组"，锁一个应锁整体，否则能绕过半边图形移动另一半。

## 二、关键决策链路

**1. 锁定状态存哪？**
候选：App 层新 state / GeoJSON properties。选后者（`properties.locked`）——drawings 本就是 GeoJSON 字符串整存整取，锁定标志放进 feature 后，持久化、历史栈、导出三条链路**零改动**自动生效。这是本轮最省力的决策，前提来自摸底时确认 `sameState`/`cloneState` 都是字符串级操作。

**2. 锁的粒度？**
单 feature 还是组？删除/选中本来就按 `group ?? uid` 成组，锁定若按单 feature 会出现"箭头杆锁了、箭头头没锁"的荒谬状态。定为组级，用 `lockedKeys()` 从当前图层现算集合，不额外存状态，避免与 GeoJSON 不同步。

**3. 锁定入口放哪？**
候选：属性面板里加开关 / 选中框浮动按钮。选中框已有样式、删除两个浮动按钮（`buildGizmo`），锁定是同级别的"对选中对象的操作"，放这里发现成本最低、最符合用户"再次点击可以复现锁定图标"的描述。锁定时隐藏其余按钮只留解锁，正好复用同一位置的重建逻辑。

**4. 拦截怎么做才不漏？**
先盘点所有"写入口"再逐个拦截，而不是边写边想。清单来自摸底：本体移动、手柄、捏合、套索移动、属性面板、文字编辑、橡皮擦三路（单击/整删/笔迹）、deleteSelected 三触发源（gizmo 按钮/Delete 键/工具栏）、清空本层。教训式认知：**这类"全局禁止"功能的工作量不在逻辑而在枚举入口**，漏一个就是 bug。

**5. 提示用什么机制？**
项目没有 toast。选项：引入依赖 / 复用 mobileConfirm（要点确认，打断操作）/ 自写轻提示。擦除是连续手势，弹确认框会打断得没法用；为一条提示引依赖不值。自写 2 秒自动消失的 toast（Portal + fixed 定位），并做每轮手势去重——否则橡皮擦扫过锁定图形会刷屏。

**6. "清空本层"要不要保锁定？**
用户没提。但"除非解锁否则无法擦除"的语义下，确认弹窗后全清会把锁定图形带走，属于绕过锁定的后门。决定保留锁定图形。实现上仿照已有的 `deleteSelectedTick` 先例加 `clearDrawTick` 信号，让真正持有 GeoJSON 的 LayerManager 执行过滤，而不是在 App 层解析字符串——保持"LayerManager 是唯一写入口"的既有架构。

**7. 图标怎么用美术资源？**
两个 SVG 是 iconfont 1024×1024 填充式，与 icons.tsx 的 16×16 描边体系不一致。gizmo 按钮是 Leaflet DOM innerHTML，直接内联 SVG 字符串 + `fill="currentColor"` 最贴合现有按钮实现；同时在 icons.tsx 按本文件风格补导出，让美术资源有统一代码入口。

## 三、缩放跟随 bug 的复盘

- 现象：缩放后图标脱离图形。根因是**两套坐标系混用**：选中框是经纬度边界（随地图缩放），按钮/手柄是按屏幕像素偏移算出的 Marker（一次计算，之后不动）。
- 这个 bug 在锁定功能之前就存在（样式/删除按钮同样漂移），锁定按钮只是让它更显眼。修的是公共重建时机（`zoom`/`zoomend` → `buildGizmo`），不是只修锁定图标。
- 选 `zoom` 连续重建而非仅 `zoomend` 一次性重建：缩放动画期间图标也吸附，避免"先漂移后瞬移"的廉价感；gizmo 只有十几个 Marker，每帧重建成本可忽略。

## 四、验证缺口与风险

- 只有类型检查和构建背书，交互全靠人工点验；拦截点多达十余处，人工验证清单必须与拦截清单一一对应（见更新日志的验证入口）。
- `clearAllMapContent` 后门已知未堵，是刻意划出的范围边界，但要在日志里留痕，否则下次会被当成新 bug。
- 副本继承锁定状态未处理，属于语义待定项，等产品层面明确"复制锁定图形应该得到锁定副本还是自由副本"。

## 五、可固化的经验

1. "禁止类"需求先枚举全部写入口再动手，清单驱动，不靠记忆。
2. 数据落点优先选能"搭便车"的现有结构（这里是 GeoJSON properties），让持久化/历史/导出免费生效。
3. 同一对象的同级操作放同一 UI 锚点，状态换血（锁定时只留解锁）比逐个禁用更干净。
4. 连续手势场景不能用阻断式弹窗做提示，轻 toast + 手势级去重是正解。
5. 修表层 bug 时顺手查是否为公共机制缺陷——本次缩放漂移实际是选中框所有浮动元素的通病。
