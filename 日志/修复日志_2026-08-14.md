# 修复日志（2026-08-14）

项目：三角洲战术地图（map-tools 0.0.1）

## 修复：移动端导出战术板 HTML 无响应

### 问题

Android 端点击"导出战术板"没有任何反应。期望行为：调起系统文件管理器，由用户选择导出位置并成功保存。

### 原因

`src/platform/index.ts` 的 `downloadText` 使用浏览器下载方式（`Blob` + `<a download>` 模拟点击）。Android 的 Capacitor WebView 没有浏览器下载管理器，该点击被直接忽略。

### 改动

- 新增依赖：`@capacitor/filesystem@8.1.2`、`@capacitor/share@8.0.1`。
- `src/platform/index.ts`：Android 原生端改为先用 Filesystem 把 HTML 写入缓存目录 `exports/`，再调起 Share 系统分享面板（标题"导出到"），用户可选择"文件"应用并自选保存位置；用户取消分享不算错误。Web / Electron 端逻辑不变。
- 该修复同时覆盖模式配置器的 JSON 导出（走同一个 `downloadText`）。
- 顺带修复：`vite.config.ts` 无条件引用本地不存在的 `demo/v0.0.1/app/cinematic-demo.html` 入口导致 `npm run build` 失败，已改为文件存在时才加入构建入口。

### 打包

- 环境：JDK 21.0.12 + Android SDK（platform-36、build-tools 36.0.0），SDK 路径写入 `android/local.properties`（本机文件，不入库）。
- `npm run build` + `npx cap sync android` 后 `gradlew.bat assembleDebug` 构建成功。
- 产物：`release/deltaforce-tactical-map-0.0.1-android-debug.apk`（包名 `com.d4820.deltaforce.tacticalmap`，versionName 0.0.1，minSdk 24 / targetSdk 36）。

### 验证

- `tsc && vite build`、`cap sync`、`assembleDebug` 均通过。
- 真机已验证导出功能修复生效。
