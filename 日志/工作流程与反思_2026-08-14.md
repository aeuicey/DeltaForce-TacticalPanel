# 工作流程与反思记录（2026-08-14）

项目：三角洲战术地图（map-tools 0.0.1）
任务主线：修复 Android 导出无响应 → 搭建打包环境 → 出 APK → 推送 fork → 向上游发 PR

## 一、实际工作流程

1. **阅读聊天记录**，确认上次会话遗留待办：缺 JDK 21 与 Android SDK，打包未完成。
2. **环境检查**：发现 Java 26 已装但过新（Gradle 8.14.3 不支持），Android SDK 完全缺失。
3. **搭建工具链**：用户提供 JDK 21（`JDK21/`）；下载 cmdline-tools，sdkmanager 安装 platform-36 / build-tools 36.0.0 / platform-tools；写 `android/local.properties`。
4. **打包**：`npm run build` + `cap sync` + `gradlew assembleDebug`，输出 `release/deltaforce-tactical-map-0.0.1-android-debug.apk` 并用 aapt 核对包名/版本/SDK 级别。
5. **入库与推送**：修复日志写入 `日志/`，`.gitignore` 补充忽略 `JDK21/`，严格区分推送/本地文件后提交推送 fork。
6. **发 PR**：确认上游为 `Deng0430/delta-force`，fetch 检查冲突（无分叉），建干净分支只含 6 个修复文件，API 创建 PR 并补全描述。

## 二、踩过的坑与解决

- **Java 版本陷阱**：用户说"Java 已安装"，但装的是 Java 26，超出 Gradle 8.14.3 支持范围。教训：听到"已安装"不能想当然，必须核对**版本是否匹配构建链要求**（README 写明 Java 21）。
- **后台任务竞争**：JDK 与 cmdline-tools 两个下载并行，后者因目录尚未由前者创建而失败。教训：有依赖关系的步骤不要并行，或各自保证前置条件（`mkdir -p` 放进每条命令）。
- **sdkmanager 静默卡死**：直装时 `yes | sdkmanager --licenses` 输出全丢到 /dev/null，许可未接受，后续安装疑似卡在交互确认，且不留痕迹。教训：交互式命令不能盲加重定向；要留可观察的输出，并验证中间产物（`licenses/` 目录是否存在）。
- **网络需走代理**：dl.google.com、github.com 直连均被重置，sdkmanager（`--proxy` 参数）、Gradle（`-Dhttp(s).proxyHost`）、git（`-c http.proxy`）需分别配置，没有一处全局生效。教训：Windows 上各工具链代理配置方式不同，逐一确认。
- **git 身份缺失**：提交时报 Author identity unknown；先按历史提交猜测身份被用户纠正（fork 作者≠本机用户）。教训：身份应直接询问，历史提交的作者未必是操作者。
- **路径转义事故**：Write 工具写的 `/tmp` 在 Git Bash 与 node 中解析不一致（`/c/tmp` vs `C:\c\tmp` vs `C:/tmp`），反斜杠还被 bash 吃掉，导致 PR 首次创建时描述为空。教训：跨工具传文件用双方都能解析的路径（`C:/` 风格），创建外向产物后**必须回读验证**（PR 创建后应立刻 GET 检查 body）。

## 三、做得好的地方

- 大下载（SDK、Gradle 依赖）全部后台化，期间并行推进 Web 构建等无依赖工作，总耗时控制得不错。
- 打包后用 `aapt dump badging` + `unzip -l` 核对产物内容，而非只看 BUILD SUCCESSFUL。
- PR 与本地提交分层：fork 的 main 保留完整记录（含日志），PR 分支只带修复文件，符合"与本地相关的不用包含"的要求。
- 推送前明确列出推送/不推送清单，避免了 300MB JDK 误入仓库（`*.exe` 规则只能挡住一部分，补 `/JDK21/` 才完整）。

## 四、可固化的经验

1. 打包前环境 checklist：JDK 版本 ≤ 构建链上限、`ANDROID_HOME`/`local.properties`、sdkmanager 许可目录、代理可达性。
2. 交互式安装命令：前台跑或保留输出，装完验证产物目录。
3. 任何对外动作（push、PR）后回读验证结果，不要只看出参/退出码。
4. Windows 混合环境路径：内部工具约定统一用 `C:/` 风格绝对路径。
5. 仓库卫生：新出现的本地大件（工具链、产物）第一时间进 `.gitignore` 并 `git status --ignored` 复核。
